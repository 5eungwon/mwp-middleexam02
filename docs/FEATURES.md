# 감시 영역과 푸시 알림 개선

2026-11-10 구현 상태입니다. 새 평가용 편의 기능은 아래 두 가지입니다. 기존 검색·확인 기능은 유지합니다.

## 감시 영역 설정

**구현·로컬/클라우드 실제 검증 완료.** 웹의 감시 설정 또는 Android 목록의 `감시 영역 · 알림 설정`에서 사진 위를 드래그해 영역을 저장합니다. 이름, ON/OFF, 좌표는 사용자 계정별로 분리됩니다. 좌표는 0~1 정규화 값이며 반전·범위 초과·NaN·너무 작은 사각형은 거부합니다.

YOLO는 서버 설정을 주기적으로 조회해 사람의 발밑 중심점이 영역 안에 있는지 확인합니다. 영역 안의 클래스가 0→1로 변할 때 사진을 보냅니다. 영역 기능을 끄면 기존 전체 화면 감지입니다. 객체 ID 추적이나 사람 수 변화 감지는 구현 범위에 포함되지 않습니다.

- [실제 YOLO 로컬 검증](evidence/features-20261110/roi-integration.json): 같은 공개 예제에서 영역 밖 사람은 전송 0건, 영역 안 사람은 전송 1건.
- [실제 YOLO 클라우드 검증](evidence/features-20261110/cloud-roi/roi-integration.json).
- [Android 실제 드래그·서버 저장](evidence/features-20261110/android-zone-runtime.json).
- [클라우드 Android 검증](evidence/features-20261110/cloud-android/android-zone-runtime.json).

이는 실제 모델로 정지 이미지를 처리한 결과입니다. 사람의 이동을 합성하거나 실제 카메라를 사용했다고 주장하지 않습니다. 진입·유지·이탈·재진입 상태 전이는 별도 단위 테스트로 검증했습니다.

## 감지 푸시 알림

**발송·수신 코드와 모의 통신 테스트 준비, Firebase 프로젝트 연결 및 실제 수신 검증은 사용자 요청으로 보류.**

서버는 사진을 저장한 후 기기별 발송 작업을 DB에 기록하고 FCM HTTP v1 전송을 시도합니다. 발송 실패 때문에 사진 등록이 실패하지 않게 분리했으며, 남은 작업은 `send_pending_push` 명령으로 재시도합니다. 호스팅의 웹 프로세스 재시작으로 작업 스레드가 종료될 수 있으므로 지속 발송에는 이 명령을 예약 작업/운영 워커에 연결해야 합니다.

Android는 알림 권한, FCM 기기 토큰 등록, 기기 연결 해제, 알림 클릭 후 기록 상세 열기를 구현했습니다. 이전 계정·서버의 알림을 잘못 열지 않도록 로그인 연결 ID를 검증합니다. Firebase 파일이 없으면 설정 대기를 표시하며 알림 성공을 가장하지 않습니다.

서버 테스트의 모의 FCM 성공은 외부 서비스·휴대폰 전달 성공 증거가 아닙니다. [Firebase 설정 순서](FIREBASE_SETUP.md)를 마친 후 백그라운드 수신과 알림 클릭을 실제로 확인해야 합니다.

## 검증 기록

- Django 기존·신규 테스트 25개 통과: 영역·사용자 분리, 잘못된 좌표, 기기 소유권, 설정 없는 발송 상태, 모의 FCM 성공·실패, 기존 API/웹.
- 엣지 테스트 13개 통과: 원래 출현 변화·실제 모델 검출과 영역 진입 판정.
- Android 빌드/Lint 통과: 오류 0개, Gradle 최신 버전 안내 경고 1개.
- 수정한 배포 도구는 실제 외부 DB·미디어를 백업하고 새 DB·가상환경에 복제 후 마이그레이션합니다. 격리 SQLite 테스트와 실제 클라우드 배포에서 이전 데이터 보존을 확인했습니다.

루트 Word는 사용자가 수정 중인 기존 제출본을 보존합니다. 새 기능을 모두 완료로 표시한 최종 보고서 갱신은 실제 푸시 수신 검증 후 진행해야 합니다. 현재 캡처·상태 파일로 영역 기능 완료와 푸시 연결 보류를 구분할 수 있습니다.
